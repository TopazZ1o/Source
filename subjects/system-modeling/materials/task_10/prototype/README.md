# Прототип учёта запасов авиатехнической базы (СРМ №10)

Учебный прототип склада запасных частей и материалов для ТО и ремонта самолётов: регистрация номенклатуры (P/N), приход с сертификатом годности, доступный остаток, резервирование под заказ-наряд, снятие резерва, выдача, история движений. Python 3.11+ и встроенный `sqlite3`, сторонних пакетов нет. Пользовательского интерфейса нет, работа ведётся через методы класса `StockService`.

## Запуск (из папки `prototype`)

```
python demo.py
python -m unittest discover -s tests -t . -v
```

`demo.py` показывает приход, резерв под заказ-наряд, отказ при нехватке, повторный запрос, карантин партии без сертификата, выдачу и историю. Вывод сохранён в `demo_output.txt`, вывод тестов – в `test_results.txt`. Каждый тест создаёт свою базу SQLite во временной папке.

## Состав

| Файл | Назначение |
|---|---|
| `mro_stock/db.py` | Схема SQLite: ограничения CHECK и UNIQUE, триггеры неизменяемости журнала движений |
| `mro_stock/service.py` | `StockService`: все операции, роли, транзакции `BEGIN IMMEDIATE` |
| `mro_stock/errors.py` | Ошибки с кодами: `VALIDATION`, `FORBIDDEN`, `NOT_FOUND`, `INSUFFICIENT_STOCK`, `INVALID_STATE`, `IDEMPOTENCY_CONFLICT` |
| `tests/test_inventory.py` | 23 сценария TC-01...TC-23 и один контрольный тест без транзакции |
| `demo.py` | Демонстрация основных операций |

## Основное

- Остаток хранится в `stock_balance` и одновременно выводится из журнала `stock_movement`; `check_consistency()` сравнивает оба представления.
- Резерв оформляется под заказ-наряд (`WO-NNNN`): проверка доступного и запись резерва выполняются одной транзакцией; последний рубеж – `CHECK (reserved <= on_hand)`.
- Повтор документа (`doc_no`) и повтор резерва (`request_id`) не создают дубликатов.
- Резерв распределяется по сроку годности (FEFO); партии в карантине и просроченные недоступны.
- Партия без сертификата годности принимается сразу в карантин; снять его может только руководитель, указав номер сертификата.
- Агрегаты принимаются по серийным номерам (S/N), уникальным в пределах P/N.

## Не реализовано

Поставщики и заказы, инвентаризация, автоматическое снятие резерва по сроку, расчёт пополнения (он сделан отдельно в `../calc`), связь с системой ТО и Р из работы 9 (заказ-наряд здесь лишь строка формата `WO-NNNN`), интерфейс пользователя, нагрузочные испытания.
