# Прототип ИС ТО и ремонта самолётов (СРМ №9)

Учебный прототип, проверяющий проектные решения отчёта: правила состояния в объектах предметной области, транзакции, интерфейсы, конкурентное назначение ресурса и исключительные ситуации. Пользовательского интерфейса и реальной базы данных нет: хранилище находится в памяти.

Требуется только Python 3.11+ (сторонних пакетов нет).

## Запуск (из папки `prototype`)

```
python demo.py
python -m unittest discover -s tests -t . -v
```

`demo.py` сам переключает вывод в UTF-8 (консоль Windows использует cp866).

## Состав

| Файл | Назначение |
|---|---|
| `aircraft_maintenance/domain.py` | ВС, заявка, заказ-наряд (этапы, дефекты, запчасти, заключения), ресурс, назначение, акт списания, запись журнала, ошибки; правила состояния внутри объектов |
| `aircraft_maintenance/ports.py` | Интерфейсы: `DataStore`, `Notifier`, `AuditLog` |
| `aircraft_maintenance/storage.py` | Хранилище в памяти: транзакции с откатом, ограничения (уникальный номер, одна активная заявка на ВС, непересечение назначений), внедрение сбоя для тестов |
| `aircraft_maintenance/adapters.py` | Уведомления «в приложении» и по e-mail, неисправный канал для тестов, журнал только на добавление |
| `aircraft_maintenance/services.py` | `AccessPolicy`, `RequestValidator`, `OperationRunner`, `PlanningService`, `WorkOrderService`, `ReleaseService`, `WriteOffService`, `DeadlineService` |
| `tests/test_aircraft_maintenance.py` | 28 автоматизированных проверок (TC-01…TC-15 матрицы трассируемости и 4 дополнительные) |
| `test_results.txt` | Вывод запуска тестов |

## Что проверяют тесты

Полный цикл от заявки до допуска; неполные данные и неизвестное ВС; права и заблокированного пользователя; запрещённые переходы статусов; граничные значения (срок ТО сегодня и вчера, смежные интервалы, количество запчасти, дата заявки); одновременное назначение одного места в ангаре двумя планировщиками (20 повторов) и контрольный запуск без замка и ограничения, где возникает двойное назначение; повторную и одновременную подачу заявки на одно ВС; откат при сбое сохранения и атомарность назначения нескольких ресурсов; допуск при незавершённых этапах, открытом критичном дефекте, заключении «негодно»; списание; сбой канала уведомлений; неизменяемость журнала.

## Ограничения

Общий замок и хранилище в памяти моделируют блокировки и ограничения СУБД, но не заменяют проверку на реальной СУБД. Сбои хранилища и канала имитируются исключениями. Нагрузка и сеть не проверялись. FR-13 (история и отчёты) не реализовано.
